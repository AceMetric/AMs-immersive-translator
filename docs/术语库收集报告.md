# 术语库收集结果与依据

更新：2026-10-04，对应 AM 0.1.6。0.1.5 达到了采集数量与来源记录门槛，但用户反馈暴露了分类筛选不足；0.1.6 严格筛选后的内置候选降为 6,900 条，原定 10,000 条目标当前未达到。这不等于领域专家认证或所有语境下的翻译正确率保证。

## 目标与实际数量

| 领域 | 核心（全部完成项目编辑核对） | 扩展候选 |
| --- | ---: | ---: |
| 数学（含 Lean、类型论、形式化证明） | 511 | 3,765 |
| 物理 | 373 | 1,685 |
| 计算机 | 487 | 1,450 |
| 合计 | **1,371** | **6,900** |

六个领域包及索引位于 `public/glossaries/`，共 8,271 条。核心超过 1,000 条目标，每条均有译名、领域、词义、具体来源、证据文件和编辑说明；`npm run glossary:provenance` 检查全部实际打包核心，不只检查数量门槛。核对由 AI 辅助项目编辑完成，后续仍欢迎专业复核和错误反馈。

原始采集得到 12,495 个“领域＋实体”输入记录，基础清洗排除 1,216 条，留下 11,279 条（10,259 个不同实体）。新增严格学科筛选后，保留 6,900 条，隔离 4,141 条，明确排除 238 条。隔离与排除记录可恢复，不随扩展内置，原始快照保留。地区标签、复数和别名不重复计数；当前数量与筛选边界见 [扩展词库筛选报告](扩展词库筛选报告.md)。

候选不需要用户逐个核对才能使用。它们全部保留 `quality: candidate`，只作相关提示，不能因为开关启用就成为强制替换的核心或个人术语。长期维护优先复核高频、歧义和用户报告的条目；确认译名后再收录。

## 候选来源与清洗

扩展数据使用 Wikidata 英中标签、别名、描述及实例/子类关系，采用 CC0，不复制 Wikipedia 正文或商业词典。保留 180 份成功的完整查询快照，含查询和响应摘要、抓取时间、分类范围及结果。没有查询达到设置的结果上限；失败、截断及限流响应不会被保存为空库，成功缓存可用于续跑。

清洗按实体合并重复查询，优先简体地区标签，其次通用中文，再用 OpenCC 统一字形并保留原标签。字形转换不等于译名或语义审校。排除人物、机构、出版物、列表、货币、具体天体等越界项目；隔离无法区分词义的同名译名冲突，保留明确不同的词义。编辑确认的错误另存排除原因，例如将库仑阻塞误标为单电子晶体管的候选。

类别和关键词只是初步证据，仍可能带入不适用的词义。因此候选数量不作为质量保证，不自动升级核心。

## 核心的逐条项目核对

`data/glossary-audit/core-review.json` 保存全部 1,371 条具体记录：1,299 条引用 Wikidata 实体资料，72 条引用官方文档，其中 Lean 35 条、Google Machine Learning Glossary 16 条、其他项目文档 21 条。记录包括独立编写的定义、中文译名选择说明、实际来源链接和可定位证据，不以搜索首条或布尔“通过”代替核对。

官方参考包括 Lean 类型与证明概念、Google 机器学习词义、PyTorch 自动微分/混合精度/分布式训练、etcd 一致性与法定人数、PostgreSQL 连接、Python 条件变量、MDN 同步/异步与位掩码、OpenAI Spinning Up 强化学习、Transformers 采样和 CleverHans 对抗训练。项目文档固定 Git 提交，来源原文保留各自许可和署名，**不改标为 CC0**；详情见 [数据许可](../DATA-LICENSE.md)。

自动生成的 `core-evidence.json` 是初步标签核对队列，只含 TSV 的 1,363 条源记录（另外 8 个明确词义由构建器生成）。其中 737 条自动匹配标签及领域描述、626 条未被该简单规则支持。这个队列不代表当前审校缺口：官方文档依据、修正的译名或限定词义可以由人工编辑记录支持，最终状态以完整的 `core-review.json` 为准。

部分核对修正和范围区分：

- 可数集与可数无限集；定义域、陪域、像和原像；极大元与最大元；关系性质与日常/语言学含义。
- 环论理想与序理论理想；函数发散与向量场散度；物理量子化与计算机量化；ACID 一致性与分布式一致性。
- `disjoint-set data structure → 并查集` 使用 union-find 等明确别名，普通 disjoint sets 不强制译成并查集。
- `optical path → 光路` 与 `optical path length → 光程` 分开；Bose-Einstein condensate 指凝聚态而不是凝聚过程。
- Lean 宇宙层级与天文学宇宙、策略与国际象棋战术不混用；structure type 使用 Lean 官方定义。

## 歧义词的应用约束

增加同领域的明确词义记录，区分 remainder 的余项/余数、permutation 的排列/置换、precision 的分类精确率/数值精度、normalization 的规范化/归一化、temperature 的采样温度参数/设备温度，以及 anti-aliasing 的图像抗锯齿/信号抗混叠。

这些容易误锁定的核心词义要求明确的上下文关键词；词边界匹配避免把 preprocess 当作 process。kernel、feature、switch、module、instance、limit 等也限制其特定词义的强制应用。缺乏支持或同级词义评分相同时不锁定译名，交由模型理解或用户指定。直接用户术语和已确认术语保持更高优先级。

这是保守的规则消歧，不证明关键词出现就一定选对；标题、邻段或跨学科混合语境仍可能误导。术语图继续作为默认关闭的实验，不用未经验证的相似性关系硬性指定译名。

## 术语开关修复

核心术语禁用再启用保留核心身份，不进入“我的术语”。旧版仅由开关产生的错误个人记录会在读取时恢复分类，用户真正编辑、导入或确认的译名保留。内置词条更新时保留用户开关偏好，同时刷新定义和来源；候选开关也保留候选身份。界面统计、筛选、导出与翻译检索使用相同分类规则。

## 验证与性能边界

本次验证包括 93 项 TypeScript 测试、16 项离线采集与筛选测试、类型检查、完整词库目标校验和生产构建。测试覆盖术语禁用/启用/重开、旧记录迁移、个人覆盖、候选身份、歧义词与上下文边界，以及地区标签去重、冲突隔离、人物排除、截断不落盘、限流等待、空查询缓存和官方正文提取。

大词库原检索为所有条目创建正则，首次数学段落曾耗时约 1.87 秒、物理约 1.58 秒。现先筛选当前文字中出现的原词/别名，再进行 Unicode 词边界匹配。2026-10-04 本机 Node 26.9.0、60 段公开语料、包含候选的检索结果为：

| 领域 | 段落数 | 匹配数 | 首段检索 | 单段最大 | 中位数 |
| --- | ---: | ---: | ---: | ---: | ---: |
| 数学 | 20 | 64 | 3.20 ms | 3.20 ms | 1.28 ms |
| 物理 | 20 | 110 | 2.67 ms | 6.51 ms | 1.24 ms |
| 计算机 | 20 | 41 | 2.34 ms | 2.34 ms | 0.60 ms |

此结果只测词库检索，不是浏览器首译、模型速度或译文质量；新语境约束可能减少硬锁定匹配。不把毫秒数据保证给所有电脑。原始数据在本机 `artifacts/glossary-research/lookup-performance-current.json`，运行 `npm run glossary:benchmark` 可重测。

检查输出、最终验证摘要和打包检查保存在本机 `artifacts/glossary-research/`。这些工作文件不进入公开源码包；公开仓库保存本报告、测试与可复现来源。

## 文件与复现

- `public/glossaries/`：插件实际使用的六个领域包和索引。
- `data/wikidata/collected/`：扩展成功快照；`core-evidence/`、`core-aliases/`：核心实体依据。
- `data/primary-sources/`：官方参考文本、固定版本、许可和署名。
- `data/glossary-audit/candidates.json`：有效候选、分类来源、拒绝原因与数量。
- `data/glossary-audit/core-review.json`：逐条完成的项目编辑核对记录。
- `data/glossary-audit/core-evidence.json`：自动初步核对队列，不能代替编辑结论。
- `data/glossary-exclusions.json`：明确错误排除规则。
- `templates/glossary-contribution.json` 和 [贡献说明](../CONTRIBUTING.md)：开放贡献格式及校验要求。

```sh
npm ci
python3 -m venv .venv-glossary
.venv-glossary/bin/python -m pip install -r scripts/requirements-glossary.txt
# 复用保存的完整来源；缺失数据才联网请求
npm run glossary:fetch
.venv-glossary/bin/python scripts/audit-core-evidence.py
npm run glossary:build
npm run glossary:provenance
npm test
.venv-glossary/bin/python -m unittest discover -s tests -p '*_test.py'
npm run typecheck
npm run glossary:benchmark
npm run release
```

已有官方资料缓存不需要重新抓取；需要新增或刷新时使用相应 `collect-lean-evidence.py`、`collect-ml-evidence.py`、`collect-project-evidence.py` 工具并重新核对具体条目。Windows 的虚拟环境解释器可改为 `.venv-glossary/Scripts/python.exe`。这些流程不会下载模型或修改 Ollama 设置。
