# 词库在线更新

AM 0.1.9 起支持独立更新核心库和扩展候选库。下载并加载 0.1.9 **一次**后，后续词库更新无需覆盖插件文件，也无需重新加载插件。

## 使用

1. 打开插件设置 → 术语库 → **词库在线更新**。
2. 点击 **检查词库更新**，首次检查按 Chrome 提示授权 `raw.githubusercontent.com` 数据域名。
3. 有更新时会显示版本，以及核心库、扩展候选库的新数量；点击 **更新词库**。
4. 更新成功后，正在翻译的页面会按阅读位置重新翻译。暂停的页面继续保持暂停。原网页中的公式、代码不变。
5. 如译名不合适，点击 **回退上一版**。也可以 **恢复内置词库**，使用当前安装包附带的数据。

回退只保留一版；回退后可以再次切换回来。个人术语、长期确认的译名、编辑过的译名和启停偏好保存在独立数据库中，更新、回退不会删除它们。被新版筛掉的内置候选不会因为曾经开启过而重新进入候选库；明确编辑或确认过的个人词条仍保留。

默认不定时联网。检查更新和更新下载只由点击触发，不需要模型密钥、不发送页面原文、不消耗翻译额度。下载完成后保存在扩展 IndexedDB，离线和浏览器重启后仍可使用。关闭设置页不会取消后台下载；重新打开可看到当前版本或失败提示。

## 更新范围与失败处理

独立更新仅包含六份 JSON 词库：数学、物理、计算机的核心库及扩展候选库，不下载插件脚本、模型或其他程序。候选词仍只提供提示，不会因更新成为强制术语。

检查清单从本项目官方 GitHub `main` 获取。词库文件按清单固定到同一个不可变 Git 提交，校验 SHA-256、字节数、条目数量、类别、领域、重复 ID、文字字段、来源链接以及最低插件版本。下载采用 30 秒单文件超时和大小上限；全部通过后，一次事务提交完整快照与版本指针。SHA-256 用于完整性校验，信任来自固定官方仓库与 HTTPS，并非独立的数字签名或术语正确性证明。

断网、超时、权限未授权、文件损坏、存储失败或格式不兼容时，现有词库继续使用。需要更高版本插件的数据会提示先升级插件，不强行应用。GitHub 数据域名无法访问时，也可以使用安装包内置库。

切换词库后，旧的翻译及校润请求被取消；缓存包含词库版本，不会把旧版译文当成新版结果。已安装的在线词库优先于安装包附带词库；安装新的完整插件包后，如想采用新包附带的数据，可点击恢复内置词库，或再次检查官方更新。

## 与整个插件更新的区别

当前本地安装方式仍需通过覆盖原目录和扩展管理页“重新加载”来更新插件代码，**无需卸载或重填配置**。整个插件的自动更新留待 Chrome 正式发布渠道。

Chrome 的 Manifest V3 要求将可执行代码打包在插件内，JSON 数据不属于远程代码：[Chrome 官方说明](https://developer.chrome.com/docs/extensions/develop/migrate/remote-hosted-code)。Windows/macOS 的普通用户通过 Chrome Web Store 获取正式扩展更新：[官方分发说明](https://developer.chrome.com/docs/extensions/how-to/distribute/host-on-linux)。词库更新不绕过该限制。

## 维护者发布词库更新

更新清单为 `public/glossaries/update.json`，它记录独立的数据版本、六个词库的版本/数量/许可/校验值，以及不可变的来源提交。修改词库数据后：

1. 完成词库清洗、来源校验及测试。
2. **先在本地提交**六个词库文件及 `index.json`；此时先不推送。
3. 运行 `npm run glossary:update-manifest`，生成指向这个已提交版本的清单。
4. 运行 `npm run glossary:update-check` 和 `npm test`；提交清单。
5. 一次推送数据提交及清单提交到 `main`。用户之后检查更新即可获取。

清单不能引用包含它自身的未来提交，因此必须分两次本地提交、一次推送。生成器只读取 Git 中已提交的数据；没有提交的数据改动会在检查时被发现。源码包已附带生成好的清单，正常构建不依赖 Git 历史或远程下载。

改变 JSON 协议或词条结构需要先升级插件并提高清单中的 `minExtensionVersion`。不要把未筛选、待复核或排除池直接发布为在线候选库。CI 会核对当前六个数据文件与清单，防止陈旧清单被发布。
