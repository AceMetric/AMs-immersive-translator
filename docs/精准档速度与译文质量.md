# 0.1.3：精准档速度与中文表达

更新日期：2026-10-03。目标是降低本地精准档等待时间，并系统改善中文表达。深度思考、精准上下文和译后校润现在是独立的处理选择。

## 参考了什么，为什么没有直接套用

阅读了 [translation-agent 的固定版本源码](https://github.com/andrewyng/translation-agent/blob/e0fc605acbb5d78cb7a58a98bc8bd8f0056df49c/src/translation_agent/utils.py)，重点是 `one_chunk_reflect_on_translation` 和 `one_chunk_improve_translation`。它按准确性、流畅度、文体和术语检查译文，再根据建议修改。项目使用 MIT 许可，但这里没有复制或打包其代码、提示词或依赖；仅参考处理思路。

这个项目的完整流程是初译、生成审校建议、修改译文，通常要三次调用。它自己的 README 也明确说明质量并不总能超过商业翻译。AM 针对网页阅读和本地模型作以下取舍，效果须由实际译文验证：

- 默认一次翻译，完整约束中文表达和语义忠实度；不让每段都产生长思考过程。
- 本地精准档逐段交付，保留领域、摘要、前后文和相关术语，但消除重复上下文和长标记开销。
- 可选“译后校润”只增加一次调用：把英文原文与带保护标记的中文草稿一起交给模型，合并检查和修改，直接返回修改后的中文。它不是参考项目完整三阶段流程，是否达到相同效果尚未验证。
- 校润继续使用同一术语锁定和格式验证器，不能改写指定译名或吞掉公式、代码。损坏的校润结果不能覆盖已通过格式校验的草稿。

## 中文表达要求

不是仅替换某个错误句式，也不对模型输出作“你也欢迎 → 你也可以”的机械替换。默认翻译和校润都考虑以下维度：

| 维度 | 具体处理 |
| --- | --- |
| 准确性 | 保留事实、数字、单位、否定、量词、条件、因果方向、必要/充分条件及确定程度；邀请不能变成命令 |
| 语序与句子结构 | 按中文主题与谓语组织句子，必要时拆开长句，但保留修饰范围与从句依赖 |
| 搭配与简洁度 | 用自然动词和搭配，减少名词化、机械被动式与冗余表述；不为流畅删除论证内容 |
| 衔接与指代 | 利用相邻段落判断指代；不能随意省去造成歧义的主语，也不添加原文没有的逻辑连接 |
| 文体与语用 | 匹配原文的教材、论文或说明语气，用清楚、克制的现代中文表达，避免英文客套的字面迁移 |
| 术语一致性 | 已锁定词义沿用指定译名；扩展候选仅是提示，不强行替换；润色不能改动术语标记 |

极速档使用上述原则的精简提示，精准档和校润使用更完整的要求。它们仍是模型约束，不是自动证明翻译正确的机制。

## 使用与升级

升级保留原有模型配置。没有新字段的旧本地配置自动采用“精准档不请求深度思考”，无需用户重新设置。可在阅读侧栏或模型设置中开启：

- **深度思考**：本地精准档请求模型思考，适合确实需要额外推理的情形；默认关闭。
- **译后校润**：精准档对照英文原文审改中文草稿；默认关闭，以减少等待。它与深度思考独立，校润调用本身请求直接输出。

云端精准档原有思考策略保留。未知兼容接口仍需选择其支持的思考参数；“服务默认（不发送参数）”不等于强制关闭思考。不同模型并不一定支持禁用思考。

本地两档均每次派发一段，云端继续使用批次设置。缓存区分提示词、精准档思考选择、校润选择和实际上下文，旧提示词产生的缓存不会被误当成新版结果。切换开关会重新评估当前页面；源文变化和过期任务仍受会话与任务归属校验。

中文样例覆盖：可选邀请、存在/全称量词、非零/否定、必要条件、目的与效率之间的对比、让步与唯一性证明。检查同时包含模型实际输出、阅读页面渲染以及代码保持原样。也直接把生硬的中文草稿交给校润步骤，而不只检查正常译文能否重复返回。

格式、锁定术语的数量和嵌套关系能自动验证；语义、文体和自然程度不能仅靠标记验证。本轮是少量中文样例和一个长段落的实测，没有专家盲评、长期吞吐测试或证明所有段落都消除了翻译腔。模型仍可能输出偏书面的表达或语义错误。
