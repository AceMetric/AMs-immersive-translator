# 测试与首版边界

## 自动验证方法

```sh
npm run typecheck
npm test
npm run glossary:validate
node scripts/validate-contribution.mjs templates/glossary-contribution.json
npm run build
npx playwright install chromium
python3 scripts/snapshot-pages.py
npm run test:e2e
```

本机测试浏览器位于 `/private/tmp/am-playwright`，复用它时设置 `PLAYWRIGHT_BROWSERS_PATH=/private/tmp/am-playwright`。测试使用单独临时用户目录，退出后不会改动日常 Chrome 资料。

无头 Chrome 无法点击原生可选权限提示，因此浏览器验收只在**临时副本**中预授予 localhost/127.0.0.1 权限。正式 manifest 在测试中先断言不含 blanket host_permissions；交付包仍按需授权。UI 输入、导入、深色和窄屏均在真实扩展页面执行。浏览器弹窗的原生授权交互仍需用户在常规 Chrome 安装时验证。

固定一秒模拟响应的首译目标为两秒内；实际首译通过页面状态 firstTranslationMs 读取。真实页面结构验收使用从公开来源下载的本机 HTML 快照，保留其真实标签、公式/代码结构；外部脚本与样式请求禁用。此项证明原始节点完整，不代表所有线上站点的动态脚本均已覆盖。

真实样本来源：

- [Mathematics in Lean：Basics（用户报告页面）](https://leanprover-community.github.io/mathematics_in_lean/C02_Basics.html)
- [Mathematics in Lean：Logic](https://leanprover-community.github.io/mathematics_in_lean/C03_Logic.html)
- [arXiv HTML：2407.10939v1](https://arxiv.org/html/2407.10939v1)
- [Python：Data Structures](https://docs.python.org/3/tutorial/datastructures.html)

这些快照仅存在 ignored artifacts，版权与许可属于原作者，未打入发布包。

## 本地模型验证

用户授权后使用本机现有 `qwen3.8:27b-mlx`，没有下载模型、改动服务配置或重启服务。一次只发一个请求，默认请求上下文 8K，测试遵循不建议超过 28K 的约束。某些本地后端可能忽略请求的 num_ctx，实际模型配置应以其服务为准；插件自身仍按设置控制文字请求预算。

```sh
AM_OLLAMA_NATIVE=1 node scripts/live-ollama.mjs
PLAYWRIGHT_BROWSERS_PATH=/private/tmp/am-playwright AM_LIVE_OLLAMA=1 npm run test:e2e
```

直接接口的小样本覆盖数学、物理、计算机，检验 JSON、段落 ID、中文输出、公式/代码和指定术语标记。真实浏览器测试检查页面中文生成及原节点完整。耗时结果写入 artifacts 中的 ollama-*-report.json，不把短句测试速度当作整篇文章的速度，也不把模拟服务测试当作真实云端模型质量验证。

云端 Claude/Gemini/OpenAI 兼容协议的功能验收使用模拟服务，真实云端的质量、供应商计费和实际思考能力需配置相应有效模型后实测。

## 覆盖范围

- 最长词组、边界、别名、缩写、学科歧义、同学科不同词义、个人优先和禁用。
- CSV/TSV/JSON 导入导出、冲突预览、术语确认长期存储、相关段落更新及不相关节点保留。
- MathJax/KaTeX/MathML/SVG/原始 TeX 保护、代码/引用/链接/强调、嵌套列表、表格、动态内容、恢复原文。
- 严格标记验证、响应段数/ID、损坏批次拆分、限流有限重试、鉴权暂停、取消、缓存重新绑定。
- 32 秒模型请求在关闭侧栏并终止服务 Worker 后继续；offscreen 重建后恢复持久任务。
- 极速/精准的思考参数与领域包选择；4K 预算下压缩上下文并拆分大段，保留行内代码/公式。
- 模型发现、设置页连接测试、上下文限额保存、浅深色与 300px 窄侧栏、弹窗 Escape 与键盘焦点循环。

## 已知限制

1. 专业核心术语未完成领域专家逐条认证；候选库未达到 10,000 条建设目标。自动术语和自动领域判断可能不准，应使用手动领域和个人词条纠正。
2. 上下文按有限邻域和文章前部样本处理，不能承诺长篇未读章节中的未知术语已经一致。思考本身不保证译名正确。
3. 自绘 canvas、复杂编辑器、跨域嵌套 iframe、浏览器内部页面、PDF、扫描件不在首版范围；特殊站点可能需要调整提取规则。
4. 页面将原始 TeX 拆到多个不相关 DOM 文本节点时，定界符保护可能无法完整识别；无法渲染的公式原样保留。超大且不可拆分的格式范围超过本地预算时显示重试提示，不删除原文。
5. 任务状态可在 offscreen 重建后恢复，但完整关闭浏览器后不会未经再次点击自动发送旧页面文字。
6. 本地上下文预算采用保守估算，并非各模型的精确 tokenizer。其他兼容服务器实际上下文长度需在服务端设置。
7. 仅交付本地安装包与源码；未发布 Chrome 商店、在线贡献社区、账号/同步。

## 0.1.1 故障回归（2026-10-02）

用户报告精准档在 Lean Basics 中出现连续 JSON 错误。初次验收的真实模型测试仅覆盖普通＋极速档，未覆盖此场景。此次新增 `tests/e2e/precision.spec.ts`：直接转发到本机现有 Qwen，使用真实 C02 HTML 的 §2.4 两个报告段落，学术＋精准＋自动数学词库＋8K 上下文，检查实际中文生成及原始公式/代码节点完整；恢复后再次比对。运行前先获取本机 HTML 快照：

```sh
python3 scripts/snapshot-pages.py
PLAYWRIGHT_BROWSERS_PATH=/private/tmp/am-playwright AM_LIVE_PRECISION=1 npm run test:e2e -- precision.spec.ts
# 默认六段批次也单独验证
PLAYWRIGHT_BROWSERS_PATH=/private/tmp/am-playwright AM_LIVE_PRECISION=1 AM_PRECISION_BATCH=6 npm run test:e2e -- precision.spec.ts
```

首次复测确认：原实现前置术语分析约 69 秒，不能作为可接受首屏策略。本机 MLX 后端还明确拒绝原生 structured output（HTTP 501）；兼容路径保留思考、预算和译文验证，随后两段成功生成中文。此项观察不代表截图中原 JSON 错误只存在一个原因。

新增回归覆盖：完整包装 JSON、截断/多个对象/未闭合思考块、长度结束原因、思考无最终输出、一次直接输出恢复、原生 JSON 能力拒绝、鉴权/取消不误重试、损坏单段不影响相邻段落。39 项单元测试通过，13 项模拟浏览器测试通过（原真实极速档测试在本轮跳过，精准档单独运行）。真实模型耗时与保护节点数量写入 ignored `artifacts/precision-debug/precision-report.json`；测试请求并发为 1，未修改或重启用户模型服务。

最终 0.1.1 默认六段批次实测：首批约 **53.37 秒**，完成 6 段，失败 0 段。首个思考响应的 JSON 完整但擅自替换了锁定术语标记，严格验证将其拒绝；自动直接输出恢复保留了全部标记并成功。原始 90 个公式/代码节点在实时翻译后完整；另外回放同一组真实响应，对恢复后再次作完整比较。两段小批次此前亦成功，但不以该结果替代默认批次验收。已知 MLX 模型现在跳过无效原生 JSON 能力探测，减少额外等待。

真实精准档仍会比极速档慢，尤其首个思考响应需要恢复时；上述 53 秒是该模型、该批次的本次结果，不是速度保证。固定 1 秒模拟响应此次首译约 1.02 秒。最终构建的思考策略、后端能力恢复和单段隔离 3 项浏览器回归再次通过。
