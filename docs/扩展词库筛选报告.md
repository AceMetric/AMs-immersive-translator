# 扩展词库严格筛选

更新：2026-10-04，AM 0.1.6。用户选择：证据不足的条目移出内置库，保留可恢复的待复核池。

## 为什么会混入无关条目

0.1.5 的数量、格式和来源校验通过，但学科筛选不足。采集沿 Wikidata 分类分支扩展时，把宽泛分类关系误当作学科归属：

| 错误条目 | 实际来源分支 | 问题 |
| --- | --- | --- |
| 2011 年末世预言（Q2740637） | 预测（Q748250），来自命题分支 | 一般预测不是数学术语 |
| 九一一事件阴谋论（Q22763） | 阴谋论（Q159535），来自命题分支 | 命题的宽泛关联不能证明数学归属 |
| 作者死亡后 70 年或更长（Q29870196） | 算法（Q8366），直接类型含版权判定方法 | 行政判定规则不是本批数学/计算机术语 |

之前的“有来源”只证明标签确实来自对应实体，没有证明这个实体适合词库。以上条目已在所有相关领域移出内置候选。

## 批量筛选方法

借鉴 [Wikidata 的实例/子类关系说明](https://www.wikidata.org/wiki/Help:Basic_membership_properties)及 [Freiburg 实体链接标注指南的类型允许列表与纠错原则](https://github.com/ad-freiburg/entity-linking-annotation-guidelines)。实体链接的白名单不能直接等同于翻译词库，我们采用与数学、物理、计算机用途相符的范围规则。

筛选完全离线，复用已有来源，不逐条调用 LLM：

1. 先保留原有去重、标签安全、人物/出版物排除和明确译名错误规则。
2. 利用保存的子类父分支，整类识别阴谋论、版权状态判定、古代计谋、邮票版次、Wikidata 属性维护标记等污染来源。遇到循环终止遍历；不将 P31 当作可传递关系。
3. 使用明确的学科分支或定义信号，宽泛的“命题”“算法”等分类本身不够。存在音乐音名、音乐制作、社会学等矛盾信号时，不能仅因命中一个技术词就保留。
4. 缺少定义或定义只重复“theorem／algorithm”等泛泛类别、没有足够学科证据、证据相互矛盾、或同领域同原词与项目核心译名冲突的条目进入待复核池。译名冲突可能是合法的不同词义或地区用语，不直接判错。
5. 为每条保存决定、命中原因、来源分支和规则版本；可重放全部决定，验证“保留＋隔离＋排除”与输入一一对应。

规则在 `data/glossary-screening.json`，实现是 `scripts/glossary_screening.py`。分支聚合数量让后续维护优先处理整类问题，而不是逐条从头看。人工只需分层抽查和处理高频疑难条目；本轮抽查引导修正音乐术语等规则，未将抽查冒称全库审校。

## 实际结果

| 领域 | 0.1.5 候选 | 0.1.6 内置候选 | 待复核 | 明确排除 |
| --- | ---: | ---: | ---: | ---: |
| 数学 | 6,397 | 3,765 | 2,480 | 152 |
| 物理 | 2,584 | 1,685 | 876 | 23 |
| 计算机 | 2,298 | 1,450 | 785 | 63 |
| 合计 | **11,279** | **6,900** | **4,141** | **238** |

待复核原因：缺少具体学科证据 3,104 条、仅重复泛泛类别的定义 403 条，缺少定义 515 条，核心译名冲突 96 条，其他学科信号 22 条，来源分支与定义冲突 1 条。上述原因互斥，只按最终决定计数。明确排除中 105 条命中非本批学术主题，133 条来自越界分支/类型。

保留候选仍未经逐条专业译名审校。严格规则会暂时隔离一些有效词，例如定义缺失的公倍数和某些专业猜想；它们没有被抹掉。后续可补来源与规则重新构建，但不自动提升为核心，也不自动覆写个人译名。插件读取时忽略已被筛出的内置候选开关记录，防止旧版记录把它们重新带回；用户实际编辑或导入的个人术语仍保留。

**内置扩展库现为 6,900 条，尚不足原先 10,000 条数量目标。** 不为保住数量放回无关词。`glossary:provenance` 验证来源、核心记录和全部筛选决定；`glossary:target` 继续如实报告数量目标未达到。

## 复现与查看

```sh
# 使用此前安装的 OpenCC 数据清洗环境
.venv-glossary/bin/python scripts/clean-glossary.py
# 上一步只写预览；默认采用严格筛选
.venv-glossary/bin/python scripts/clean-glossary.py --install-packs
npm run glossary:provenance
python3 scripts/render-glossary-screening.py
```

- `data/glossary-audit/candidates.json`：保留候选、来源及每条筛选决定。
- `data/glossary-audit/candidate-quarantine.json`：待复核和明确排除的完整词条、来源、决定及原因。作为源码数据保留，**不随插件内置**。
- `artifacts/glossary-research/screening-report.html`：离线可搜索报告，支持领域、状态、原因及分支关键词过滤，分页显示和导出当前筛选 CSV。只读，不改动插件词库。
- 原始 `data/wikidata/collected/` 快照不修改，规则变化后可恢复和重新判定。

本轮规则运行约 1 秒（本机、已缓存来源，包含原有清洗与输出）；不包含联网采集、人工抽查时间，也不是其他电脑的速度保证。新增回归检查覆盖三个真实污染例子、音乐和社会学信号、普通算法不自动放行、有效几何/粒子/计算概念、子类循环与译名冲突。最终校验还重放全部 11,279 条决定，防止规则变化后沿用过时数据。

本轮没有把全文交给模型重审，没有增加新模型调用或改变 Ollama 配置。规则筛选解决范围与明显污染，译名自然度、领域专家审校和深层词义准确性仍需独立评估。
