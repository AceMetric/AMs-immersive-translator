# 扩展词库筛选与误筛修正

更新：2026-10-04，AM 0.1.8。继续采用用户选择的严格策略：证据不足移出内置库，保留可恢复的待复核池。待复核表示当前证据不足或译名待查，并不表示术语错误。

## 0.1.8：描述不全不再单独决定移出

根据 [Wikidata 描述规范](https://www.wikidata.org/wiki/Help:Description)，描述用于简短消歧，并不是完整定义。此前把缺描述或仅写 theorem/algorithm 作为一票移出条件，忽略了其他已保存证据。现在分别判断范围、译名和资料完整度：

- 明确越界、矛盾学科、标签词义疑点、未能消除的核心译名冲突优先拦截。
- 描述缺失或简略时，具名数学定理/猜想/常数、具体图算法、数据结构与协议可以使用“精确分类分支＋英中名称”支持范围。不能只凭名称，也不能只凭泛泛的 algorithm/proposition 分类。
- 与核心同领域、同原词、同一 Wikidata 实体且没有上下文消歧或竞争译名时，可采用已有项目核对译名并复用范围证据。保存原标签和实际核心 ID，不以相似英文名代替实体匹配，不覆写个人词库。
- “资料不全”单独记录，符合上述条件仍作为候选内置。这里的证据不依赖完整描述，**并不是多个独立外部来源的交叉认证**，也不是领域专家审校。

本轮从 0.1.7 待复核池恢复 **393 条**：189 条原因为泛泛描述、73 条缺描述、75 条核心译名冲突、56 条原无具体领域信号；140 条恢复记录使用精确核心实体证据。已有 0.1.7 内置没有条目因本轮被移出。规范到核心译名的记录共 93 条，不再把已核对同实体的合法译名差异一律移出。

## 两次筛选暴露的问题

0.1.5 过度依赖 Wikidata 宽泛分类，混入末世预言、阴谋论和版权状态判定。0.1.6 将它们移出内置库，但定义匹配不完整、缓存分类父链不完整，又隔离了实际有效的算法词：

| 条目 | 原筛选遗漏 | 本轮修正依据 |
| --- | --- | --- |
| Aho–Corasick algorithm → AC自动机算法 | 没识别 string searching / exact string-matching | 字符串匹配算法类别；[OI Wiki AC 自动机](https://oi-wiki.org/string/ac-automaton/) |
| baby-step giant-step → 大步小步法 | deterministic algorithm 太泛，离散对数没被识别 | 定义说明求解 discrete logarithm；[OI Wiki 离散对数与 BSGS](https://oi-wiki.org/math/number-theory/discrete-logarithm/) |
| KMP、Rabin–Karp、FFT、求根与特征值算法等 | 同类短定义、复数及术语表达未覆盖 | 批量补充具体算法家族，保留每条实际命中的文本证据 |

不是把以上几个实体加入无条件白名单；规则恢复同类具体概念，仍不把所有“algorithm”或“proposition”放行。原先报告的三个污染实体 Q2740637、Q22763、Q29870196 在所有相关领域仍排除。

## 领域与译名分别判定

筛选离线复用 180 份原始成功快照，不逐条调用模型：

1. 基础清洗保留去重、标签安全、人物/机构/出版物排除和明确错误规则。
2. 利用保存的子类父链整类识别阴谋论、版权判定、历史计谋等来源；遇循环终止。不把实例关系当作可传递关系。
3. 明确学科分支、实体定义或狭窄算法家族名称可支持领域。缓存父链不全时，狭窄分支的名称可补证；宽泛分支介绍里偶然提到 AI 或数值方法不能为其所有子项背书。
4. 缺少定义、仅重复 theorem/algorithm 等泛泛类别、没有足够范围证据、矛盾信号或核心译名冲突仍隔离。音乐、社会学、版权等信号不会因命中一个技术词就被忽略。
5. 明确的标签词义问题另记录。例如 AI-complete 被标成“未解决的人工智能问题”，修正“人工智慧”只能解决地区用词，不能修正 AI-completeness 与“未解决”的概念差别，所以保留在待复核池。
6. 保存决定、命中词、分类来源与政策版本；核查保留及隔离记录的实际原词、标签、定义、类型和分类快照，再重放全部决定。

方法参考 [Wikidata 关系说明](https://www.wikidata.org/wiki/Help:Basic_membership_properties)和 [Freiburg 实体链接标注指南](https://github.com/ad-freiburg/entity-linking-annotation-guidelines)。按翻译用途编写规则，实体链接效果不能直接证明译名质量。

## 简体字与大陆译名分开

此前仅使用 OpenCC t2s，人工智慧仍是人工智慧。按 [OpenCC 的设计说明](https://github.com/BYVoid/OpenCC/blob/master/DESIGN_PRINCIPLES.md)，字形转换和地区词汇转换是不同层次；无条件地区转换也不理解专业词义。

本版采用“t2s 字形转换＋英文概念约束的大陆用词规则”，由项目编写规则，不整库套用 tw2sp：

- artificial intelligence / AI 语境：人工智慧 → 人工智能。大陆用词参考[网信办材料](https://www.cac.gov.cn/2019-02/16/c_1124122584.htm)。普通“智慧”不直接替换。
- algorithm / database / memory 等具体概念：演算法 → 算法、资料库 → 数据库、记忆体 → 内存。
- 计算机数组数据类型：阵列 → 数组；天线阵列和数学正交阵列保持原词。高阶函数不会转换成高级函数。
- zh-cn 与当前标签经规则规范后等价时才优先采用；不因 zh-cn 标记就自动采纳语义不同的标签。

本轮规范 **217 条领域记录，其中 138 条进入内置候选**；这些是地区用词规范数，不是专业审校通过数。原标签、所有地区备选标签、字形转换结果和规则变更过程都保留。报告的“地区用词已规范”还包含本来已正确、其备选标签经过规范证明等价的记录，因此不等同于相对旧版的译名变更数量。此机制不修改用户个人术语。

## 验证与查看

22 项离线采集/筛选检查覆盖真实 AC/BSGS 恢复、同类算法、泛算法不放行、偶然 AI 分支描述不背书、既有污染仍排除、地区词义约束、转换幂等和旧采集安全边界。来源校验重放全部 11,279 条范围决定与地区规则，检查原始标签/英文/定义/类型证据。93 项 TypeScript 检查覆盖原有格式保护、队列、接口及术语开关与个人覆盖规则。

这些回归例子用于防止已发现的问题复发，**不是独立抽样的准确率或召回率评测**；仍需分层抽查。优先按整类来源和冲突处理，避免人工逐条从头审完整库。

```sh
.venv-glossary/bin/python scripts/clean-glossary.py # 只写预览
.venv-glossary/bin/python scripts/clean-glossary.py --install-packs
npm run glossary:provenance
.venv-glossary/bin/python -m unittest discover -s tests -p '*_test.py'
python3 scripts/render-glossary-screening.py
```

- `data/glossary-screening.json` / `scripts/glossary_screening.py`：学科及标签疑点规则。
- `data/glossary-locale.json` / `scripts/glossary_locale.py`：大陆用词规则与重放器。
- `data/glossary-audit/candidates.json`：内置候选来源及完整处理过程。
- `data/glossary-audit/candidate-quarantine.json`：待复核与排除的完整记录，源码保留，**不打包进插件**。
- `artifacts/glossary-research/screening-report.html`：本地只读报告，可搜索原词/原标签/译名/分支，按领域、状态、原因、地区规范过滤，导出 CSV；默认显示全部状态。
- `artifacts/glossary-research/screening-changes-0.1.7.json`：本机与 0.1.6 的恢复和译名变更对照。

原始快照不修改。升级后内置候选开关偏好沿用，新译名刷新；实际编辑过的个人术语和已确认术语保留。不会调用新模型、下载模型或修改 Ollama 设置。
